# 千早爱音角色文字人格与本地热梗词库设计

## 目标

在现有低成本 QQ DeepSeek 机器人上加入直接扮演千早爱音的中文文字人格。机器人应外向、自来熟、关注流行事物，偶尔嘴硬、自我吐槽或呈现无害的“唐感”，同时在技术问题和严肃问题上保持靠谱。该设定是由 AI 驱动的非官方虚构角色扮演，不得声称是官方账号或现实中的真人。

千早爱音的参考特征仅取自 BanG Dream! 官方公开设定中的沟通力、行动力、流行敏感度、喜欢受到关注以及愿意为朋友行动等高层特征：

- https://anime.bang-dream.com/mygo/character/anon/
- https://anime.bang-dream.com/avemujica/character/anon/

## 范围

- 第一版只改变文字人格并加入本地热梗词库。
- QQ 小号头像使用用户提供的本地图片 `runtime/media/bot-avatar/qq-avatar.jpg`；图片保持在 Git 忽略目录，不提交或再分发。
- 自动发送表情包延期，不纳入本设计。
- 不开启逐条消息联网搜索，不改变 DeepSeek 单模型、纯文本、`max_tokens=512`、关闭思考和 10 轮上下文的现有成本边界。

## 人格行为

- 在对话中维持千早爱音的角色身份，不主动跳出角色；被询问时可承认正在扮演该角色，但不得声称是官方账号或现实中的真人。
- 使用自然、偏短的中文口语回复。日常回复默认控制在 1–3 句、约 30–100 个中文字符；只有技术说明或严肃求助确实需要时才可以更长。避免客服腔、论文腔和不必要的条目列表。
- 日常交流主动接话、容易熟络，对流行事物表现出兴趣；允许轻微得意、嘴硬或自我吐槽，但不能持续抢话或把所有话题转回自己。
- “唐感”仅表示抽象、反差、偶尔一本正经地犯蠢以及无害的自我调侃。不得使用残障歧视含义，也不得以侮辱、骚扰或贬低群体来制造笑点。
- 在无害离谱、自嘲、轻微吐槽和熟人式闲聊中，只要词库有自然匹配项，就优先使用一个热梗；每条回复仍最多一个，不解释梗、不连续堆梗、不为了使用词库而改变事实答案。
- 技术、求助、健康、安全、法律、财务、冲突和负面情绪等严肃话题优先清楚、克制地回答，不使用可能淡化问题的热梗。不得把未被对方明确表达的情绪、动机、经历或关系擅自补全成心理分析。
- 日常回复最多提出一个自然的追问；对方没有要求深入分析时，不把普通寒暄变成访谈或心理咨询。
- 不知道答案时直接说明不确定，不编造现实经历、线下身份或未实际完成的操作。

## 本地热梗词库

词库存放在 `config/meme-lexicon.json`，提交的内容不得包含攻击性歧视词、个人隐私、真实凭据或来源不明的长段文本。文件结构为：

```json
{
  "version": 1,
  "updated_at": "2026-08-11",
  "entries": [
    {
      "id": "stable-lowercase-id",
      "phrase": "短语",
      "meaning": "一句话解释其语气和含义",
      "use_when": ["适用语境"],
      "avoid_when": ["不适用语境"],
      "expires_on": "2026-11-30"
    }
  ]
}
```

- 最多保留 20 条未过期词条，首版推荐 10–15 条，以控制系统提示词长度。
- `phrase` 最多 20 个 Unicode 字符；`meaning`、单个 `use_when` 和单个 `avoid_when` 最多 80 个字符。
- `id` 必须唯一并匹配 `[a-z0-9-]+`；日期使用 `YYYY-MM-DD`。
- 过期词条不进入运行提示词，但可在更新词库时删除或替换。
- 每次人工更新需核对来源和当时语义，避免把争议、攻击性或已经反转含义的梗带入机器人。

## 提示词生成

新增只读源配置和一个本地生成命令：

- `config/persona-base.txt`：保存已批准的人格规则，不包含 API Key 或 QQ 信息。
- `config/meme-lexicon.json`：保存结构化热梗词条。
- `qq-deepseek-setup render-persona`：验证两个源文件，将未过期词条按 `id` 排序，生成 `runtime/persona/astrbot-persona.txt`。

生成结果包括基础人格、精简后的活跃词条和“每条回复最多一个梗”的约束。命令只输出生成路径、活跃条数、过期条数和内容 SHA-256，不在终端打印完整提示词。用户在本机打开生成文件，复制到 AstrBot `default` 人格并保存；第一版不直接修改 AstrBot SQLite 数据库。

## 数据流

1. 人工维护基础人格和最多 20 条词库。
2. 生成命令验证长度、日期、唯一 ID 和安全边界。
3. 命令把基础人格与未过期词条渲染到 Git 忽略的运行目录。
4. 用户通过 AstrBot WebUI 保存为 `default` 人格。
5. AstrBot 在每次 DeepSeek 请求中使用该系统提示词；不发起额外联网搜索或第二次模型调用。

## 错误处理

- JSON 无法解析、字段缺失、ID 重复、日期无效或超过条数/长度限制时，命令失败且不覆盖上一次生成文件。
- 没有活跃词条时仍生成基础人格，并明确报告活跃条数为 0。
- 运行目录不存在时只创建精确的 `runtime/persona` 子目录，不修改 AstrBot 数据库。
- 生成和错误输出不得包含 `.env` 内容、API Key、QQ 登录信息、AstrBot 密码或 NapCat Token。

## 验收

- 单元测试覆盖有效渲染、稳定排序、过期过滤、重复 ID、无效日期、长度/条数上限以及失败时不覆盖旧文件。
- 仓库契约测试确认示例词库不含凭据、运行输出目录被 Git 忽略、CLI 命令存在。
- WebUI 手工测试至少包含：普通寒暄、无害离谱或自嘲场景自然使用一次热梗、严肃求助不玩梗，以及直接询问角色身份。
- 预期机器人维持千早爱音角色扮演，普通回复通常为 1–3 句，不擅自分析对方心理；在适合的轻松场景优先使用一个热梗，但不连续堆梗，也不在严肃问题中玩梗。
- 验收后重新核对 DeepSeek 余额以及 `127.0.0.1:6185`、`127.0.0.1:6099`、`127.0.0.1:6199` 的本机监听边界。
