# QQ DeepSeek 对话机器人第一版设计

## 目标

在一台 Windows 电脑上运行一个低成本 QQ 对话机器人。机器人通过 QQ 小号登录，仅在私聊或群聊中被明确触发时调用 DeepSeek，并将回复发送回原会话。

第一版优先保证部署简单、费用可控、会话不串线和密钥不泄露，不加入本地模型、知识库、联网搜索、语音或多模型路由。

## 系统边界

系统由以下组件组成：

1. NapCatQQ：连接 QQ 小号，提供 OneBot v11 消息收发接口。
2. AstrBot：处理触发规则、会话隔离、上下文、人设、队列和错误回复。
3. DeepSeek API：使用 `deepseek-v4-flash` 的非思考模式生成文本回复。

消息流：

```text
QQ 小号
  -> NapCatQQ
  -> AstrBot
  -> DeepSeek V4 Flash API
  -> AstrBot
  -> NapCatQQ
  -> 原 QQ 会话
```

## 平台和运行方式

- 主机系统：Windows。
- QQ 接入：NapCatQQ，使用专门的 QQ 小号扫码登录。
- 机器人框架：AstrBot。
- 模型服务：仅 DeepSeek，不配置第二模型，也不安装 Ollama。
- 第一版以本机运行和人工启动为主；自动开机启动不在第一版范围内。

## 消息触发规则

- 群聊仅响应 `@机器人` 或配置的触发关键词。
- 私聊默认响应；可通过拒绝列表关闭不需要的联系人。
- 机器人自身发送的消息不得再次触发机器人。
- 第一版不主动插话，也不处理所有群消息。
- 第一版不安装额外的非文本处理插件；图片、语音、视频和文件由 AstrBot/NapCat 默认忽略或提示不支持，并且关闭图片描述、语音识别等会产生额外模型调用的能力。

## 会话与上下文

- 每个 QQ 私聊联系人使用独立会话。
- 每个 QQ 群使用独立会话；第一版群内所有成员共享该群的对话上下文。
- 每次模型请求最多携带最近 10 轮有效对话。
- 达到上下文限制后，较早消息不再原样发送；由 AstrBot 支持的上下文压缩能力生成摘要时使用摘要，否则直接丢弃最早消息。
- 不在两个模型之间同步上下文，因为第一版只有 DeepSeek。
- 提供 `/reset` 命令清空当前会话上下文；管理员 QQ 号通过本机配置指定。

## 模型调用策略

- 模型：`deepseek-v4-flash`。
- 模式：非思考模式，面向快速日常聊天。
- 单次回复最大输出长度默认为 512 Token，可在配置中调低。
- 通过自定义请求体明确设置 `{"thinking":{"type":"disabled"}}`，避免默认启用思考模式。
- 使用 AstrBot 和 DeepSeek SDK 的默认超时及瞬时错误处理，不增加本地代理、独立请求队列或额外自动重试。
- 不同时请求多个模型，不基于回答质量自动重试，从而避免重复计费。

## 费用控制

- 群聊必须明确触发，避免读取每条消息都调用模型。
- 限制最近上下文轮数和单次最大输出长度。
- AstrBot 平台限流设置为 60 秒内最多处理 5 条消息，超出后丢弃，防止刷屏和恶意消耗。
- DeepSeek 仅充值可接受损失的小额余额，不依赖自动续费作为第一版控费手段。
- 提供本机余额查询脚本，调用 DeepSeek 官方 `/user/balance` 接口；管理员还可以通过 AstrBot `/stats` 和 DeepSeek 控制台检查用量。
- 第一版不实现每日硬上限、独立计费面板或本地 API 网关。

## 配置与安全

- DeepSeek API Key 只保存在本机环境文件中。
- 仓库只提供 `.env.example`，真实 `.env` 必须被 Git 忽略。
- NapCat 和 AstrBot 的管理端口默认仅绑定本机，除非后续明确配置局域网访问和认证。
- 日志不得记录 API Key、完整鉴权头或 QQ 登录凭据。
- 日志可以记录时间、会话类型、匿名化会话标识、请求结果和耗时，便于排错。
- 机器人应明确以机器人身份回复，不冒充真人。

## 错误处理

- DeepSeek 超时或临时错误：使用 AstrBot 默认错误处理，不在项目中叠加重试。
- API 鉴权失败或余额不足：停止继续重试，在日志中标记配置错误，并向管理员提示。
- NapCat 断开：AstrBot 保持运行并等待重连；尚未发送的回复允许丢弃，会话历史仍由 AstrBot 保存。
- 不支持的消息类型：沿用 AstrBot/NapCat 的默认忽略或不支持提示，不增加 DeepSeek 调用。

## 项目交付内容

当前仓库将包含：

- Windows 环境下的安装和启动说明。
- AstrBot、NapCatQQ 与 DeepSeek 的配置模板。
- `.env.example` 和安全的 `.gitignore`。
- 启动前检查脚本，用于检测依赖、端口和必要配置，但不保存用户密钥。
- DeepSeek 余额查询脚本，只显示余额状态且不输出 API Key。
- 配置与辅助逻辑的自动化测试。
- 从安装、QQ 扫码、API Key 配置到发送首条测试消息的验收步骤。

## 测试与验收

自动检查至少覆盖：

- 缺少必要配置时给出明确错误。
- 示例配置不会包含真实密钥。
- 群聊触发、私聊触发和机器人自身消息过滤规则符合设计。
- 会话键能够区分不同私聊和不同群聊。
- 上下文最多保留设计规定的轮数。
- 自定义请求体关闭思考模式，并将最大输出长度限制为 512 Token。
- 余额查询失败时返回非零退出码，并且不会输出 API Key。

人工验收步骤：

1. 启动 NapCatQQ 并使用 QQ 小号扫码登录。
2. 启动 AstrBot，确认其已连接 OneBot v11。
3. 配置本机 DeepSeek API Key。
4. 在私聊中发送测试消息并收到回复。
5. 在群聊中验证未 `@` 时不回复、被 `@` 时回复。
6. 验证不同私聊和群聊之间不会共享上下文。
7. 暂时填入无效 API Key，验证不会无限重试或泄露密钥。

## 第一版明确不做

- 本地 Qwen/Ollama。
- 第二模型或自动模型切换。
- 微信接入。
- 图片理解、语音识别、语音合成和文件分析。
- 知识库、联网搜索和外部工具调用。
- 主动发言、情感陪伴记忆和跨群长期记忆。
- 公网管理面板、商业化多租户和自动计费。

这些能力可以在第一版稳定运行并得到真实聊天反馈后单独设计。
