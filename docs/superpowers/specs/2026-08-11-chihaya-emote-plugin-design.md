# 千早爱音随机表情包插件设计

## 目标

在现有 NapCatQQ + AstrBot + DeepSeek 机器人中加入本地随机表情包能力。用户主动请求“来只千早爱音”时不调用 DeepSeek，直接返回一张随机图片；正常的 DeepSeek 文字回复可以低频附带一张图片。发图行为必须受会话级和全局级滚动额度控制，避免群聊刷屏、费用浪费和额外 QQ 风控。

## 用户行为

- 私聊发送精确文本 `来只千早爱音` 时直接返回一张图片。
- 群聊沿用现有唤醒边界：用户需要 `@机器人` 后发送 `来只千早爱音`；插件按 AstrBot 已去除 At 组件后的正文匹配，不监听未唤醒的普通群消息。
- 为兼容 AstrBot 的命令习惯，同时接受正文前后空白和一个可选的 `/`，但不做模糊匹配，避免日常聊天误触。
- 主动请求不进入 LLM，不增加 DeepSeek token 消耗，也不写入对话上下文。
- 正常 LLM 文字回复在满足概率、冷却和额度条件时，在同一消息链末尾附带一张图片。
- 插件只处理 QQ/NapCat 和其他能发送本地图片的 AstrBot 平台事件；WebChat 可展示图片但不作为首版验收重点。

## 发图规则

两种入口共享同一组滚动额度：

- 普通聊天附图概率：每次最终 LLM 回复为 `20%`。
- 会话冷却：同一私聊或群聊的两张图片至少间隔 `300` 秒。
- 会话额度：任意滚动 `3600` 秒内最多成功预留 `3` 张。
- 全局额度：全部会话合计任意滚动 `3600` 秒内最多成功预留 `10` 张。

判断顺序为：图片池可用 → 会话冷却 → 会话额度 → 全局额度 → 普通聊天概率。主动请求跳过概率判断，但仍受冷却和两层额度限制。

主动请求被冷却或额度拦截时，从本地固定列表随机返回一句短提示，不调用 LLM。首版提示包括：

- `没有啦，每小时只有三只`
- `每小时只有 3600s，你先省着点`
- `本小时爱音浓度已经超标`
- `三只已经越狱完了，下个整点再来`
- `库存 0 只，尊严也不多`

普通聊天附图被冷却或额度拦截时只保留原文字回复，不追加提示。图片在加入待发送消息链时即计入额度；即使后续平台发送失败也不回滚，以保持风控边界偏保守。

## 架构

采用独立 AstrBot 插件，不修改 AstrBot、NapCat 或 DeepSeek 核心代码。

插件包含四个边界明确的组件：

1. **触发器**：规范化消息正文，只识别批准的主动请求文本，并在匹配后停止后续 LLM 处理。
2. **图片池**：启动时递归扫描插件运行目录下的 `emotes` 子目录，接受 PNG、JPG、JPEG、GIF 和 WebP；忽略隐藏文件、零字节文件和不支持的扩展名。
3. **滚动额度器**：使用单调决策逻辑管理会话冷却、每会话 3 张和全局 10 张额度，并通过异步锁保证并发事件不会超额。
4. **回复装饰器**：只对 `is_llm_result()` 的最终非流式回复执行 20% 抽样，满足条件时把本地图片组件追加到结果链。

插件配置提供以下首版默认值，并允许在 AstrBot 插件配置中调整：

- `chat_probability = 0.20`
- `session_cooldown_seconds = 300`
- `session_hourly_limit = 3`
- `global_hourly_limit = 10`
- `window_seconds = 3600`

输入配置必须验证范围；非法值回退到已批准默认值并写入不含账号信息的警告日志。

## 图片资产

当前本地图片来源为用户原有 40 张和补充下载的 93 张，共 133 张。部署步骤把它们复制到 Git 忽略的插件运行目录 `runtime/astrbot/data/plugins/chihaya_emotes/emotes`：

- 对内容计算 SHA-256，完全重复的文件只保留一份。
- PNG、JPG、JPEG 和 GIF 保留原格式。
- Telegram WebP 在部署时使用 Pillow 转换为 PNG，以减少 QQ/NapCat 本地图片兼容差异；转换失败的单张图片被跳过并报告汇总，不阻断其他图片。
- 图片二进制和来源目录不提交到 Git；仓库只提交插件代码、测试、部署逻辑和文档。
- 随机选择避免与同一会话上一张完全相同；图片池只有一张时允许重复。

## 状态与隐私

额度状态写入插件运行目录的 `quota-state.json`，保存全局时间戳、按会话划分的时间戳和每会话最后一次图片时间。每次读取或预留前删除超过滚动窗口的数据。

- 会话键使用 AstrBot 会话标识的 SHA-256 摘要，不把原始 QQ 号、群号或昵称写入状态文件。
- 状态更新采用临时文件加原子替换，避免进程中断留下半个 JSON。
- 状态文件损坏时移到带时间戳的隔离文件，使用空状态继续运行并记录安全摘要；不在日志打印文件内容。
- AstrBot 重启后继续遵守重启前一小时内的额度，不通过重启绕过上限。

## 数据流

### 主动请求

1. AstrBot 收到已唤醒的私聊或群聊事件。
2. 插件规范化正文并匹配 `来只千早爱音`。
3. 在异步锁内清理过期时间戳并检查冷却、会话额度和全局额度。
4. 有额度时预留一次、持久化状态、随机选图并返回本地图片结果，同时终止后续 LLM 处理。
5. 无额度时返回随机短提示并终止后续 LLM 处理。

### 普通聊天

1. 现有 DeepSeek 流程生成最终文字结果。
2. 发送前装饰钩子确认结果来自 LLM，且不是流式中间片段、错误消息或插件命令结果。
3. 插件在满足 20% 概率、5 分钟冷却和两层额度时预留一次并持久化。
4. 本地图片组件追加到原结果链；任何不满足条件的情况都保持原文字结果不变。

## 错误处理

- 图片池为空：主动请求回复 `今天一只都没跑出来，图片库存好像空了`；普通聊天保持纯文字。
- 被选图片在发送前消失：重新扫描一次并尝试另一张；仍失败则保持纯文字或返回库存错误，不反复重试。
- 单张图片无法读取：将其从当前内存池排除并记录文件名摘要，不暴露绝对用户路径。
- 状态写入失败：本次不发送图片，避免无状态时突破额度；原 LLM 文字回复保持可用。
- 插件内部异常不得中断原有 DeepSeek 文字回复，日志不包含 API Key、NapCat Token、QQ 号或完整会话标识。

## 测试与验收

自动化测试覆盖：

- 主动请求正文规范化、可选 `/` 和非精确文本不误触。
- 主动请求不产生 LLM 请求，并能返回本地图片结果。
- 20% 抽样边界可通过注入随机数稳定测试。
- 同一会话 300 秒冷却。
- 滚动 3600 秒内每会话最多 3 张、全局最多 10 张。
- 第 3600 秒后旧记录过期，不出现固定整点双倍突发。
- 主动请求与普通附图共享同一额度。
- 两个并发会话不会突破全局额度。
- 状态保存、重启恢复、损坏文件隔离和会话键脱敏。
- 图片池扩展名过滤、SHA-256 去重、WebP 转 PNG、空池及文件消失降级。
- 回复装饰器只修改最终 LLM 结果，不修改命令结果、错误结果和空结果。

本机验收顺序：

1. 重新加载插件，确认 133 张源图经转换和去重后的实际池数量大于 0。
2. 私聊发送 `来只千早爱音`，确认直接收到图片且 DeepSeek 调用日志没有新增。
3. 群聊 `@机器人 来只千早爱音`，确认收到图片；未 At 的普通群消息不触发。
4. 同一会话连续请求至额度上限，确认收到随机怪话而不是图片。
5. 在两个以上会话验证每会话 3 张和全局 10 张边界。
6. 使用可测试配置暂时提高附图概率，确认普通 LLM 文字回复后能附图且文字不丢失；随后恢复 20%。
7. 重启 AstrBot，确认一小时内配额仍保留。
8. 确认 QQ、NapCat、AstrBot 和 DeepSeek 原有回复链路无回归，三个服务端口仍只监听 `127.0.0.1`。

## 非目标

- 首版不让 LLM 决定具体表情语义，也不做图片内容识别或向量检索。
- 不从运行中的机器人自动联网抓取新图片。
- 不提供用户上传、删除或管理图片的 QQ 命令。
- 不修改现有每会话每分钟 5 条的 AstrBot 文本限流。
- 不把表情包二进制提交到公共仓库或重新发布第三方素材。
