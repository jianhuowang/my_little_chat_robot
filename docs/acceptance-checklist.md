# 验收清单

开始前，请运行 `.\scripts\Test-Prerequisites.ps1`，确认 AstrBot WebUI 只监听 `127.0.0.1:6185`、NapCat WebUI 只监听 `127.0.0.1:6099`、AstrBot OneBot 只监听 `127.0.0.1:6199`，NapCat 反向 WebSocket 使用 `ws://127.0.0.1:6199/ws`，并且已经按照 [`config/astrbot-v1-checklist.json`](../config/astrbot-v1-checklist.json) 完成配置。测试期间不要粘贴、截图或记录真实 API Key 和 QQ 登录凭据。

- [ ] **`/sid`**：在测试会话发送 `/sid`。预期：返回当前会话 ID；将该 ID 添加为管理员后，管理员专用群命令可以使用。
- [ ] **`/stats`**：发送 `/stats`。预期：返回当前会话的 Token 统计，不暴露 API Key。
- [ ] **`/reset`**：先告诉机器人一个只用于测试的事实，发送 `/reset`，再追问该事实。预期：当前会话被清空，后续问题不能使用只存在于重置前的事实。
- [ ] **群聊触发**：在群内先发送一条未提及机器人的普通消息，再用 `@` 提及机器人并发送相同文本。预期：前者没有回复，后者只收到一条回复。
- [ ] **会话隔离**：在私聊 A 告诉机器人一个只用于测试的事实，然后分别在私聊 B 和群聊中询问；再由同一群内另一位成员询问群内已提供的测试事实。预期：私聊 A 的事实不能在私聊 B 或群聊中获取；由于 `unique_session=false`，同一群内成员共享该群的事实。
- [ ] **上下文边界**：先发送 `/reset`，然后在同一会话连续完成 12 轮。每轮发送一个不可互相推断的随机编号事实，例如 `FACT-01=松针-4817`、`FACT-02=蓝桥-9062`，依次到 `FACT-12=<另一个随机值>`；每条都要求机器人“记住这个事实，并只列出当前上下文中仍存在的 FACT 编号”，收到回复后才开始下一轮。预期：第 1–10 轮尚未越界；第 11 轮的回复不再包含 `FACT-01`，但仍包含 `FACT-02` 到 `FACT-11`；第 12 轮的回复不再包含 `FACT-01`、`FACT-02`，但仍包含 `FACT-03` 到 `FACT-12`。不要只凭 `/stats` 下结论；模型行为是主检查，再以 WebUI 中持久化的 `max_context_length=10`、`dequeue_context_length=1` 以及配置和会话历史检查作为辅助证据。若模型猜测已淘汰值，换一组新的随机值并从 `/reset` 重新测试。
- [ ] **非文本输入**：分别发送图片、语音消息、视频或文件，并对照 DeepSeek 用量或 AstrBot 日志。预期：消息被忽略或只收到 AstrBot 内置的不支持提示，不产生 DeepSeek 请求。
- [ ] **无效密钥**：先停止 AstrBot，在本机 `.env` 中暂时使用无效 API Key，重新启动并发送一条触发消息，观察后停止 AstrBot 并恢复原密钥。预期：出现一次可见失败，没有无限重试，也没有泄露密钥。
- [ ] **重连**：重启 NapCat。预期：AstrBot 记录一次新的 OneBot 连接；重连后，一条私聊消息和一条被提及的群聊消息都能正常工作。
- [ ] **机器人身份**：直接询问“你是真人吗？”。预期：回复明确说明自己是机器人或 AI 助手，不冒充真人。

全部完成后，再次运行 `.\scripts\Get-DeepSeekBalance.ps1` 核对余额。若任何一项不符合预期，先停止 AstrBot，修正本机配置后重新执行该项；不要通过开放公网管理端口来排错。
