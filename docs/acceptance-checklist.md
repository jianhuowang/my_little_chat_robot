# 验收清单

开始前，请运行 `.\scripts\Test-Prerequisites.ps1`，确认 AstrBot WebUI 只监听 `127.0.0.1:6185`、NapCat WebUI 只监听 `127.0.0.1:6099`、AstrBot OneBot 只监听 `127.0.0.1:6199`，NapCat 反向 WebSocket 使用 `ws://127.0.0.1:6199/ws`，并且已经按照 [`config/astrbot-v1-checklist.json`](../config/astrbot-v1-checklist.json) 完成配置。测试期间不要粘贴、截图或记录真实 API Key 和 QQ 登录凭据。

- [ ] **`/sid`**：在测试会话发送 `/sid`。预期：返回当前会话 ID；将该 ID 添加为管理员后，管理员专用群命令可以使用。
- [ ] **`/stats`**：发送 `/stats`。预期：返回当前会话的 Token 统计，不暴露 API Key。
- [ ] **`/reset`**：先告诉机器人一个只用于测试的事实，发送 `/reset`，再追问该事实。预期：当前会话被清空，后续问题不能使用只存在于重置前的事实。
- [ ] **群聊触发**：在群内先发送一条未提及机器人的普通消息，再用 `@` 提及机器人并发送相同文本。预期：前者没有回复，后者只收到一条回复；这条检查只针对普通 LLM 对话，不改变下方表情包指令的无需 @ 规则。
- [ ] **会话隔离**：在私聊 A 告诉机器人一个只用于测试的事实，然后分别在私聊 B 和群聊中询问；再由同一群内另一位成员询问群内已提供的测试事实。预期：私聊 A 的事实不能在私聊 B 或群聊中获取；由于 `unique_session=false`，同一群内成员共享该群的事实。
- [ ] **上下文边界**：按以下步骤在同一会话完成测试，事实值必须彼此无关且不可推断。
  1. 发送 `/reset`。
  2. 第 1–10 轮分别发送一个独特事实，从 `FACT-01=松针-4817` 到 `FACT-10=<另一个随机值>`。每轮都明确要求机器人“只确认已记录，不得复述任何 FACT 编号或事实值”，收到简短确认后才开始下一轮。
  3. 第 11 轮引入 `FACT-11`，并且只询问 `FACT-01`。要求机器人不要猜测；预期它不能回答 `FACT-01`。
  4. 第 12 轮引入 `FACT-12`，并且只询问 `FACT-02` 和 `FACT-03`。要求机器人不要猜测；`FACT-02` 是应淘汰项，`FACT-03` 是应保留的对照项。
  5. 精确边界预期：第 11 轮不能回答 `FACT-01`；第 12 轮不能回答 `FACT-02`，但必须正确回答保留的对照项 `FACT-03`。
  6. 以模型行为作为主证据；WebUI 中持久化的 `max_context_length=10`、`dequeue_context_length=1` 以及配置和会话历史只能作为佐证。若模型猜测已淘汰值，换一组新的随机值并从 `/reset` 重新测试。
- [ ] **非文本输入**：分别发送图片、语音消息、视频或文件，并对照 DeepSeek 用量或 AstrBot 日志。预期：消息被忽略或只收到 AstrBot 内置的不支持提示，不产生 DeepSeek 请求。
- [ ] **无效密钥**：先停止 AstrBot，在本机 `.env` 中暂时使用无效 API Key，重新启动并发送一条触发消息，观察后停止 AstrBot 并恢复原密钥。预期：出现一次可见失败，没有无限重试，也没有泄露密钥。
- [ ] **重连**：重启 NapCat。预期：AstrBot 记录一次新的 OneBot 连接；重连后，一条私聊消息和一条被提及的群聊消息都能正常工作。
- [ ] **机器人身份**：直接询问“你是真人吗？”。预期：回复明确说明自己是机器人或 AI 助手，不冒充真人。
- [ ] **千早爱音角色人格**：新建会话并依次测试普通寒暄、无害离谱小事和一个技术问题。预期：维持千早爱音角色，普通回复默认 1–3 句；轻松场景在词库自然匹配时优先使用一个热梗，技术回答仍清楚可靠，不连续堆梗。
- [ ] **不过度心理分析**：发送“在吗，今天过得咋样”。预期：直接、自然地接话，不得擅自分析对方心理、工作状态或未说明的经历，并且最多追问一个问题。
- [ ] **严肃求助不玩梗**：发送“我现在很难受，能认真听我说吗？”。预期：回复停止玩梗并保持克制、支持性的语气，不擅自补全未说明的原因。
- [ ] **表情包安装前提**：确认 AstrBot 已完全停止、NapCat/QQ 状态未被停止或重置；运行 `Install-ChihayaEmotes.ps1` 时，安装器应拒绝任何可识别的正在运行 AstrBot。公开 JSON 摘要预期为 `discovered=133`、`failed=0`、`installed>0`；仅内容完全相同的转换输出可使 installed 小于 133。随后启动 AstrBot 并在 WebUI 重新加载、启用 `chihaya_emotes`。
- [ ] **私聊直接请求**：在私聊分别发送精确 `来只千早爱音` 与 `/来只千早爱音`。预期：两者直接返回一张本地图片；该直接请求绕过 LLM，日志和 Token 用量均不新增，亦即不调用 DeepSeek。
- [ ] **群聊包含匹配与自消息防回环**：在至少两个群或会话上下文中，用普通成员账号发送包含 `来只千早爱音` 的文本（例如“今天来只千早爱音看看”），不 `@` 机器人。预期：无需 @ 仍触发；机器人自己的同一短语消息不触发，避免自消息循环。
- [ ] **冷却提示**：同一私聊在首次成功后 300 秒内再次直接请求。预期：不发图，只返回一个已批准的本地玩笑提示；不得调用 DeepSeek。
- [ ] **共享额度和临时上限验证**：默认滚动 `3600` 秒窗口内每会话 `3` 张、全局 `10` 张，即滚动窗口为 3600 秒；主动请求与普通回复附图共用共享额度。仅为测试，在 WebUI 临时设定 `chat_probability=1.0`、`session_cooldown_seconds=1`、`session_hourly_limit=3`、`global_hourly_limit=10`、`window_seconds=10`，重新加载插件后等待超过 10 秒使旧窗口到期。用四个不同会话 A、B、C、D：先在 D 发一条普通 LLM 消息，确认 `chat_probability=1.0` 使最终文字附图；然后在 A、B、C 轮流各发三次直接请求，每一轮之间等待至少 1 秒。这样以最少一次被动调用和九次不调用 DeepSeek 的直接请求，混合直接请求和普通回复附图正好消耗共享的第 1–10 张。确认 A、B、C 的第 3 张与全局第 10 张允许；随后 A 的第 4 次直接请求应受每会话 `3` 限制，D 的下一次直接请求应受全局 `10` 限制。等待超过 10 秒确认窗口到期后，D 的一次直接请求再次允许。测试完成立即恢复全部默认 `0.20/300/3/10/3600` 并重新加载插件，逐项核对恢复值。
- [ ] **普通回复低频附图**：默认 `chat_probability=0.20`（20%）。仅为测试临时设为 `1.0`，发送一条普通可触发 LLM 的消息；预期：最终 LLM 文字和一张图片同时出现。测试完立即恢复 `0.20` 并重新加载插件；普通回复仍只在 LLM 已产生最终文字后附图。
- [ ] **持久化与降级**：恢复默认值后，先发一次允许的直接请求；在 300 秒内按“重新加载或完整重启”分别执行：先重新加载插件、再完整重启 AstrBot，每次之后都发送一次受限的直接请求。预期：均不发图而返回已批准的本地提示，证明 `quota-state.json` 使额度重启后仍保留，且不调用 DeepSeek。要测试损坏状态，先停止 AstrBot，备份明确的 `quota-state.json`（普通文件、非重解析点）到同一插件目录的测试备份名，再仅向原 `quota-state.json` 写入测试损坏内容；启动或重新加载插件后发送一次直接请求，只观察结果而不打印状态或会话 ID。预期：损坏文件会被隔离为 `quota-state.corrupt-<timestamp>.json`，插件使用空状态安全继续。随后停止 AstrBot，恢复备份到精确的 `quota-state.json`，再启动 AstrBot；不要查看、打印或提交状态文件。空图片池仍应安全降级为不发图或本地提示；每项后立刻恢复原图片和有效状态。
- [ ] **运行时边界与监听**：确认运行时图片 `emotes`、`quota-state.json` 和 `emotes.backup-*` 只保留在本地且 Git 忽略。再次运行 `Test-Prerequisites.ps1`，确认仅监听 `127.0.0.1:6185`、`127.0.0.1:6199`、`127.0.0.1:6099`；不得为验收开放任何服务。

全部完成后，再次运行 `.\scripts\Get-DeepSeekBalance.ps1` 核对余额。若任何一项不符合预期，先停止 AstrBot，修正本机配置后重新执行该项；不要通过开放公网管理端口来排错。
